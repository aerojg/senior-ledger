# 침해 대응 절차

누군가 허락 없이 내 코드나 앱을 복제해 공개하거나 판매하는 것을 발견했을 때의 순서입니다.
당황하지 않고 **증거를 먼저 남기고, 그다음 요청**합니다.

## 1단계 — 증거 남기기 (가장 먼저, 삭제 요청보다 앞서)

- [ ] 발견한 페이지의 주소(URL)를 적는다
- [ ] 화면 전체를 캡처한다(주소창과 날짜·시간이 보이게)
- [ ] 발견한 날짜와 시간을 적는다
- [ ] 복제된 부분이 어디인지(파일명, 문구, 화면) 내 원본과 나란히 비교해 적는다
- [ ] 내 쪽 증거를 모은다: 저장소의 커밋 이력(최초 커밋 날짜), 릴리스 태그, 내 저장소 주소

> 나중에 상대가 페이지를 지워도 증거가 남도록 캡처와 메모를 Drive의 `99_보관`처럼
> 안전한 곳에 저장해 둡니다.

## 2단계 — 상대 확인

- [ ] 단순 실수(출처 표시 누락 등)인지, 의도적인 복제인지 가늠한다
- [ ] 라이선스로 허용하는 범위(읽기, GitHub 안의 Fork)인지 확인한다(`LICENSE` 참고)
- [ ] 허용 범위를 넘으면 3단계로 간다

## 3단계 — 요청과 신고

1. **정중한 연락(가능하면 먼저)**: 상대에게 연락할 방법이 있으면 허락 없는 사용임을 알리고
   내려 달라고 요청한다.
2. **플랫폼에 삭제 요청**: GitHub 안의 복제는 GitHub의 저작권 침해 신고(DMCA) 절차를 이용한다.
   스토어나 호스팅 서비스에 올라간 경우는 해당 서비스의 저작권 신고 양식을 이용한다.
3. 신고할 때 붙일 것: 내 원본 주소, 복제본 주소, 비교 설명, 증거 캡처.

> 신고 양식의 정확한 이름과 위치, 필요한 문구는 서비스마다 다르고 바뀔 수 있으니
> 신고하기 전에 해당 서비스의 최신 안내를 확인합니다.

## 4단계 — 기록하기

- [ ] 인수인계서 변경이력에 발견 날짜, 대응 내용, 결과를 남긴다
- [ ] 같은 일이 되풀이되면 저작권 등록(한국저작권위원회)과 상표 출원을 재검토한다

## 심각한 경우

수익이 걸려 있거나 상대가 응하지 않으면 변호사나 한국저작권위원회 상담을 받습니다.

※ 이 문서는 일반적인 안내이며 법률 자문이 아닙니다.
