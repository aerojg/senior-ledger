# 비밀 점검표

이 저장소는 **공개 저장소**일 수 있습니다. 한 번 올라간 비밀은 지워도 기록(커밋 이력)에
남으므로, **올리기 전에** 점검합니다.

## git push 하기 전에 확인할 것 (매번)

- [ ] 비밀번호, API 키, 토큰, 인증서 파일이 코드나 설정 파일에 들어 있지 않다
- [ ] 실제 이름, 전화번호, 주소, 계좌번호, 주민등록번호 등 개인정보가 들어 있지 않다
- [ ] 시험용 데이터는 가짜 값만 쓴다(실제 소비 내역, 실제 문자 원문 금지)
- [ ] 화면 캡처, 영상 파일, 녹화 원본에 개인정보가 보이지 않는다
- [ ] 개인 이메일을 쓰지 않았다(커밋 이메일은 GitHub 가림 주소)
- [ ] `.env`, `*.key`, `*.pem`, `secrets*` 같은 파일이 올라가는 목록에 없다
- [ ] 개발용 시험 화면이나 임시 파일을 공개 주소로 배포하지 않는다

## 확인 방법 (PowerShell)

올리기 전에 어떤 파일이 올라가는지 눈으로 봅니다.

```
git status
```

```
git diff --staged --stat
```

## 계정과 권한 점검 (프로젝트 시작할 때, 3개월마다)

- [ ] GitHub 계정에 2단계 인증이 켜져 있다
- [ ] 도메인 관리 계정(가비아 등)에 2단계 인증이 켜져 있다
- [ ] 저장소에 쓰기 권한을 가진 사람이 나 혼자이거나, 믿는 사람뿐이다
- [ ] 저장소 `Settings`에서 `Collaborators`에 모르는 사람이 없다
- [ ] 도메인 만료일을 달력에 기록해 두었다

## 이미 비밀을 올려 버렸다면

1. 먼저 **그 비밀을 무효로 만듭니다**(키 재발급, 비밀번호 변경). 저장소에서 지우는 것보다 먼저 합니다.
2. 그다음 저장소에서 파일을 지우고 다시 올립니다.
3. 이력에 남은 것까지 지우는 방법은 복잡하므로, 필요하면 Claude와 함께 한 단계씩 진행합니다.

※ 이 문서는 일반적인 안내이며 법률·보안 자문이 아닙니다.
